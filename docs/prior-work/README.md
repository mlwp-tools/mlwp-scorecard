# Prior work: other scorecards

Notes on three existing scorecard tools, and how they compare with each other and
with this package. Each has its own note with the evidence:

- [`harp.md`](harp.md) covers **harp**, the R verification toolkit
  (`bootstrap_verify` / `plot_scorecard`). It was read from the article and the
  source.
- [`ecmwf-scorecard.md`](ecmwf-scorecard.md) covers the **ECMWF IFS cycle
  scorecard**, probably generated by Quaver. It was reverse-engineered from
  `scorecards-47r1ENS.html` and its embedded data.
- [`brightband/`](brightband/README.md) covers **Brightband Operational
  WeatherBench**. It was read from the JS bundles, the methodology page and the
  JSON API, with scripts that re-derive it.

The three cards answer different questions. Each shows a different combination of
**size of the difference** and **confidence in it**.

## What question each card answers

| | harp | ECMWF | Brightband OWB |
|---|---|---|---|
| Question | Is model A better than model B, and how sure are we? | Did the new IFS cycle improve on the old one? | How does every model compare with baseline X? |
| Sources compared | One pair (`fcst_model` vs `ref_model`) | One pair (experiment vs control) | N models against one baseline |
| Truth | Common: station observations joined to both models | Common: analyses **and** observations, both on the card | **Different per model**: each model's own analysis (IFS for some models, ERA5 for precipitation) |
| Case set | Common (`common_cases()`) | Paired (the error-bar sizes imply it) | Not common: each model pools whichever runs it has in the window |

Only harp and ECMWF compare like with like. On the Brightband card, a coloured cell
mixes model skill with differences in the truth and in the case set.

## What a cell shows

| | harp | ECMWF | Brightband |
|---|---|---|---|
| One cell is | parameter × lead time × score | truth × variable × level × region × metric, with 15 lead-time boxes inside | model × variable × lead time |
| Size of the difference | **not shown** | box fill = normalised difference (≈ % relative) | background = % difference, log scale, blank within ±1 %, saturating at ±50 % |
| Confidence | symbol shape, size and fill at 68 / 95 / 99.7 % | box border at 95 %, or triangles at 68 / 95 / 99.7 % | **none** |
| Text in the cell | none | none (hover shows "T+24 0.964% better (417)") | the model's own score value |
| Case count | not shown | on hover | not shown, and not available from their data |

The size/confidence split is the clearest way to tell them apart:

- **harp shows confidence only.** A big solid triangle can be a 0.1 % difference
  that happens to be very consistent.
- **Brightband shows size only.** A deep blue cell can rest on three cycles, and
  nothing marks it.
- **ECMWF's box mode shows both**, on separate channels. This is the design
  PLAN.md's *Significance is not size* section argues for. Its triangle mode drops
  the size and becomes the same as harp.

## How they are laid out

| | harp | ECMWF | Brightband |
|---|---|---|---|
| Rows | parameter | truth → variable → level | model (baseline pinned first) |
| Columns | lead time, one panel per score | region → metric | variable → lead time (6 leads) |
| Region | a filter | a column axis (10 regions) | a drop-down selector |
| Metric | a panel axis | a column axis | fixed per variable, implied |
| Density | small, one card per model pair | about 15,000 values on one page | about 600 values per region and mode |

## How significance is worked out

| | harp | ECMWF | Brightband |
|---|---|---|---|
| Method | paired bootstrap over pools (stations or dates), then the fraction of draws where one model wins (`percent_better`) | normal-distribution test on the paired mean difference (inferred from the data) | none |
| What gets resampled | stations or dates | forecast cases | — |
| Better or worse | closeness to a perfect-score table, so bias is handled | red/blue for errors; purple/green for spread and activity | flipped only for scores where higher is better; spread is marked directionless |

## Where mlwp-scorecards sits

Closest to ECMWF: two sources, a common truth, a paired case set, and size and
confidence on separate channels. It improves on ECMWF with a block bootstrap, the
case count on the card and an explicit polarity table.

Each of the other two has one idea worth taking:

- **From Brightband:** rows as models against one baseline, and printing the value
  in the cell.
- **From harp:** pooling by station for the resampling. That would only work for us
  if upstream kept station as a dimension in the scores.
